# Data dictionary

What is in the Hub's dataset: the 17 columns the chat can read, the 19-column layout of the full-dataset download, how each platform's export maps into them, and the flag codes. The design behind it is in the [spec](specs/2026-10-20-data-hub-design.md) (sections 5, 6 and 9).

## The dataset in one paragraph

The dataset has **one row per person per event**: an attendance record. A person is only counted once per event. The same person across events is linked by NetID first, then by email. Event details come from the form staff fill in at upload. Attendee details are copied from the platform export, exactly as recorded, and are blank where the export left them blank. The Hub never fills a blank from another source or file.

## The chat view: `attendance_view`

The AI can read only this view, and nothing else in the database. It is the GPSRC layout **without Student ID** and without the original raw row.

| Column | Type | Meaning | Blank when |
|---|---|---|---|
| `person_key` | number | An internal ID for the person, the same across events and platforms. Count `DISTINCT person_key` for "unique people". | The row had neither a NetID nor an email (unlinked). |
| `event_name` | text | Event name from the upload form. An event is identified by name and term together. | Never |
| `event_date` | date | Day of the event from the form. | Staff did not enter it. Common. 12twenty exports never supply it. |
| `term` | text | UCI quarter, like `Fall 2026`. | Never |
| `academic_year` | text | Like `2026-27`. Derived from `term`: Fall 2026, Winter 2027, Spring 2027 and Summer 2027 are all `2026-27`. | Never |
| `modality` | text | `In Person`, `Virtual` or `Hybrid`. | Never |
| `sponsors_hosts` | text | Hosts or partners, several joined with ` / `. | Staff did not enter it. |
| `event_type` | text | Category, for example `Professional Development`. | Never |
| `platform` | text | `CampusGroups` or `12twenty`, where the record came from. | Never |
| `first_name` | text | First name as recorded. | The export left it blank. |
| `last_name` | text | Last name as recorded. | The export left it blank. |
| `email` | text | Email, in lowercase. | The export left it blank. |
| `netid` | text | UCI NetID, in lowercase. | CampusGroups: the Net ID column is blank. 12twenty: no email, or the email is not a plain `netid@uci.edu` address. |
| `affiliation` | text | Role, for example `Doctoral Student`, `Master’s Student` (with a curly apostrophe), `Postdoc`. | CampusGroups: not answered. 12twenty: both degree fields blank. |
| `domestic_international` | text | `Domestic` or `International`. | CampusGroups: not answered. 12twenty: always blank, because 12twenty does not record it. |
| `school` | text | UCI school. | The export left it blank. |
| `department` | text | Department or program, free text as entered. | The export left it blank. |

Every row means the person attended. Events with no records do not appear.

## The full-dataset download

**Dataset page, then "Download full dataset (.xlsx)" or "(.csv)".** It has the 19 columns of the sponsor's *GPSRC Data Project Template*, with the template's exact header text (including its spelling, such as "Parnters"). It is the only place Student ID appears. Rows are ordered by event, then by row number in the original file.

| Column in the download | Comes from |
|---|---|
| Student Worker | The "Entered by (student worker)" field on the upload form. |
| Event Date | Form: Event date. |
| Event Term | Form: Term. |
| Event Name | Form: Event name. |
| Virtual/ In-Person/ Hybrid | Form: Format. |
| Sponsor/Host/Parnters | Form: Sponsor/Host/Partners. |
| Event type (Professional Development, Wellness/Mental Health, Fellowships) | Form: Event type. |
| On Campus Groups? | `Yes` for CampusGroups files, `No` for 12twenty files. |
| If not on Campus Groups, where was attendance found? State where + Link it | Form: Attendance source note. |
| First Name of Attendee, Last Name of Attendee, Email | The export (see the mapping below). |
| Affiliation | The export. |
| Student ID or Employee ID | CampusGroups: the `Student ID #` column. 12twenty: blank. |
| NetID | The export (see below). |
| Domestic or International | The export. 12twenty: blank. |
| School, Department | The export. |
| Notes | Generated by the Hub from the platform and the flags (see below). |

**Notes** looks like `Source: CampusGroups export; INCOMPLETE: email missing; CHECK: NetID/email conflict`. `INCOMPLETE:` lists blank fields (email/NetID unavailable, NetID missing, email missing, affiliation missing, degree missing, school missing, department missing, domestic/international missing). `CHECK:` lists identity and email flags that need a human look (non-standard email, NetID/email conflict, email belongs to another person).

Cells that start with `=`, `+`, `-` or `@` are written as text, so spreadsheet programs do not treat them as formulas.

## How each platform's export is mapped

Files are detected by their column names, not by file name. Extra columns are allowed (CampusGroups registration-form questions vary from event to event). A column that is missing leaves the value blank and sets the usual `missing_...` flag. A file that matches neither platform is rejected, and the card lists the missing columns.

| Layout column | CampusGroups export | 12twenty export |
|---|---|---|
| Identifying columns | `First Name`, `Last Name`, `Email`, `Net ID`, `Event Registration UID` | `First Name`, `Last Name`, `Email`, `Registration Date`, `Attended?` |
| Rows kept | All rows | Only rows with `Attended?` = `YES`. Others are skipped and counted. |
| First, Last name | `First Name`, `Last Name` (the profile copy). If blank, the registration-form copy (`First name`, `Last name`). | `First Name`, `Last Name` |
| Email | First `Email` column. If blank, the second `Email` column. Lowercased. | `Email`, lowercased |
| NetID | `Net ID`, lowercased | Taken from the email, only when it is exactly `letters-and-digits@uci.edu`. Otherwise blank, and the row gets `non_standard_email`. |
| Student ID | `Student ID #` | Blank |
| Affiliation | The long "Please select what you identify as…" column | `Degree`: Doctoral becomes Doctoral Student, Masters becomes Master’s Student, Postdoctoral becomes Postdoc. If `Degree` is blank: `Degree Level` (Doctorate, Masters, Postdoctoral Scholar), and the row gets `missing_degree`. |
| Domestic or International | The "international or domestic" question column | Blank |
| School | `School (drop down menu)` | `College/School` |
| Department | `Department` | `Major/Academic Program` |
| Event date (prefilled) | From `Event Registration UID`, which looks like `CG-20261015-001` | Never prefilled |
| Event name (prefilled) | From the file name, without the extension. ` - ` becomes `, ` | Same |

All text is trimmed, empty cells become blank, and emails and NetIDs are lowercased. The original row is kept inside the database, but it is never shown in the chat view.

## How people are linked

Exact matches only, applied in file order:

1. The row has a NetID that already belongs to a person: link by NetID.
2. The row has a new NetID, but its email belongs to a person with no NetID: link to that person and attach the NetID. If that person already has a different NetID, the row is linked by its NetID and flagged `netid_email_conflict`.
3. The row has no NetID but an email that belongs to a person: link by email.
4. Nothing matches, but the row has a NetID or email: a new person is created.
5. The row has neither: it is kept without a person (`person_key` is blank) and flagged `missing_identity`.

A second row for the same person in the same event is skipped and flagged `duplicate_in_event`. Names are never used for matching.

## Flag codes

Stored with each import in the `data_quality_flag` table (one row per flag, with the source row number). Staff see them as tags on the upload card, with the wording from the user guide's [flag table](user-guide.md#flags).

| Code | Platform | Meaning |
|---|---|---|
| `missing_identity` | Both | No NetID and no email. The row has no person. |
| `missing_netid` | Both | NetID blank (12twenty: also whenever the email is not a plain `netid@uci.edu`). |
| `missing_email` | Both | Email blank. |
| `missing_school` | Both | School blank. |
| `missing_department` | Both | Department blank. |
| `missing_affiliation` | Both | Affiliation blank. |
| `missing_domestic_international` | CampusGroups | Domestic/International blank. |
| `missing_degree` | 12twenty | `Degree` blank. Affiliation came from `Degree Level`. |
| `non_standard_email` | 12twenty | The email is not a plain `netid@uci.edu` address, so no NetID was derived. |
| `netid_email_conflict` | Both | The row's email belongs to a person with a different NetID. Linked by NetID. |
| `email_owned_by_other` | Both | The row's email already belongs to another person. |
| `duplicate_in_event` | Both | The same person twice in one file. The second row is skipped. |
| `not_attended_skipped` | 12twenty | Row not marked as attended. Skipped. |

New codes can be added later without a database change (the data quality feature in the backlog relies on this).

## Other tables (for developers)

The chat cannot read these. See the spec's [data model](specs/2026-10-20-data-hub-design.md#5-data-model).

| Table | Holds |
|---|---|
| `import_file` | Each uploaded file with its original bytes, hashes (for duplicate detection), status, and who uploaded it. |
| `event` | One event per committed file. |
| `person`, `person_identifier` | People and their NetIDs and emails. |
| `attendance` | The rows described above, plus the original row as JSON. |
| `data_quality_flag` | The flags. |
| `llm_profile` | The AI models, with the API key stored encrypted. |
| `conversation`, `chat_turn` | The chat history. Each turn logs the question, SQL, row count, which model answered, and whether results were shared. It is also the query log. |
| `app_user` | The single local user. |
