# S4: Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The complete staff UI:

- upload with event details;
- streaming chat with answer cards, clarifications, follow-ups, and the profile drop-down;
- LLM settings;
- dataset export.

A Playwright test covers the upload → ask → Excel path against the Docker stack with the fake model, and a second Playwright spec captures the midterm screenshots.

**Architecture:** Feature folders under `frontend/src/features/`. Every HTTP call goes through `src/api/client.ts`. Server state is held in TanStack Query. The live chat turn is a pure reducer over SSE events, so it can be tested without React.

**Tech Stack:** React 19, TypeScript, Vite, MUI 9 + MUI X DataGrid 9 (MIT), TanStack Query 5, react-router 8, react-dropzone 20, Vitest + React Testing Library, Playwright 1.64.

**Spec:** `project/docs/specs/2026-10-20-data-hub-design.md` (Sections 7.6, 8.2, 9, 10, 11). The backend contracts are in the Interfaces blocks of `2026-10-20-s2-foundation-import.md` (Task 8: imports, events) and `2026-10-20-s3-chatbot.md` (Task 2: profiles; Task 8: chat).

## Global Constraints

- Paths are relative to `project/frontend`. Commit rules are as in `CLAUDE.md`.
- `fetch` is called only in `src/api/`. An ESLint `no-restricted-globals` rule enforces this, with an override for `src/api/**`.
- `AuthGate` wraps all routes, and `/api/me` drives the user display (spec §11). There is no login UI.
- **API keys never live in the browser.**
  - The key field is `type="password"` with `autocomplete="off"`, and it is always empty when editing.
  - The stored key is shown only as `api_key_hint`.
  - Saving with an empty key field omits `api_key` from the PATCH body.
  - Nothing is written to `localStorage` except UI conveniences (the last selected profile id).
- UI copy is in English. Fixed strings:
  - Step labels: `generating` → "Writing SQL", `checking` → "Checking the query", `running` → "Running the query", `repairing` → "Fixing the query (attempt N)", `analyzing` → "Analyzing results".
  - Per-question sharing switch (spec D2), next to the question box: label "Let AI see the results"; helper text "Off: AI only writes the SQL. Results stay on this computer."; tooltip when the profile doesn't allow sharing: "This AI model isn't allowed to receive results. Change it in Settings."
  - Analysis label when `source == "llm"`: "AI-generated summary. Check it against the table."
  - Re-run label: "Re-run on current data".
- The result table is the authority. It uses DataGrid with page size 100. When `truncated`, it shows "Showing the first N rows. Export to get all rows."
- Export buttons call `apiDownload` for `/api/chat/turns/{id}/export?format=xlsx|csv` and `/api/dataset/export?format=…`.
- Routes: `/` → `/chat`; `/chat`; `/chat/:conversationId`; `/upload`; `/dataset`; `/settings`.

## Review Focus

1. **The stream drops mid-answer** (API restart, network loss). Expected: the live turn shows "Connection lost. Retry.", the composer is enabled again, and Retry resends the same question. The test is in Task 4.
2. **Pressing Enter twice, or sending while an answer is still streaming.** Expected: exactly one request; the composer is disabled until `done` or `error`. The test is in Task 5.
3. **Leaving the conversation mid-stream.** Expected: the request is aborted (AbortController) and no state updates follow. The test is in Task 5.
4. **Reloading an old conversation.** Expected: turns render from `TurnOut` without rows, with a "Show results" button that calls `/rerun` and labels the table "Re-run on current data". The test is in Task 5.
5. **Dropping 10 files at once.** Expected: each card keeps its own form state, and committing one card does not reset the others. The test is in Task 3.

### Task 1: API layer (upload, download, SSE, types)

**Files:**
- Create: `src/api/sse.ts`, `src/api/types.ts`, `src/api/sse.test.ts`
- Modify: `src/api/client.ts`, `src/api/client.test.ts`, `eslint.config.js`

**Interfaces:**
- Consumes: `apiGet`, `apiSend`, `ApiError` (S2 Task 11)
- Produces:
  - `apiUpload<T>(path: string, files: File[]): Promise<T>` (multipart field `files`)
  - `apiDownload(path: string): Promise<string>`. Fetches a blob, takes the file name from `Content-Disposition`, triggers the download through an object-URL anchor, and returns the file name.
  - `streamSse(path: string, body: unknown, onEvent: (e: SseEvent) => void, signal?: AbortSignal): Promise<void>`. Uses POST and a `ReadableStream` reader with `TextDecoder`. A non-2xx status rejects with `ApiError`. A stream that ends without `done` rejects with `ApiError(0, "stream_interrupted")`.
  - `createSseParser(onEvent: (e: SseEvent) => void): (chunk: string) => void`, a pure parser for `event:`/`data:` blocks separated by a blank line.
  - `type SseEvent = { event: "step" | "clarification" | "sql" | "result" | "analysis_delta" | "analysis" | "error" | "done"; data: any }`
  - `types.ts` mirrors the backend schemas by name: `ImportPreview`, `EventDraftOut`, `EventDetailsIn`, `CommitSummary`, `ImportFileOut`, `EventOut`, `LlmProfileOut`, `LlmProfileIn`, `LlmProfilePatch`, `PresetOut`, `ProbeResultOut`, `ConversationOut`, `ConversationDetail`, `TurnOut`, `QueryResultOut`, `MeOut`.

### Task 4: Live chat turn reducer and stream hook

**Files:**
- Create: `src/features/chat/chatStream.ts`, `src/features/chat/useChatStream.ts`, `src/features/chat/chatStream.test.ts`

**Interfaces:**
- Produces:

```ts
export type StepName = "generating" | "checking" | "running" | "repairing" | "analyzing";
export interface LiveTurn {
  question: string; status: "streaming" | "done" | "error";
  step?: { name: StepName; attempt?: number };
  sql?: { sql: string; interpretation: string; assumptions: string[] };
  result?: QueryResultOut; analysisText: string;
  analysis?: { text: string; source: "llm" | "local"; results_shared: boolean };
  clarification?: string; error?: { code: string; message: string }; turnId?: number;
}
export function startTurn(question: string): LiveTurn;
export function chatStreamReducer(turn: LiveTurn, e: SseEvent): LiveTurn;
export function stepLabel(step: { name: StepName; attempt?: number }): string;  // Global Constraints labels
export function useChatStream(conversationId: number): {
  live: LiveTurn | null; resultsByTurnId: Record<number, QueryResultOut>;
  send(question: string, llmProfileId: number | null, shareResults: boolean): void; retry(): void; abort(): void;
};
```

- `useChatStream`:
  - calls `streamSse(\`/api/conversations/${id}/messages\`, {question, llm_profile_id, share_results}, ...)`;
  - on `done`, stores `result` under `turnId` and invalidates `["conversation", id]`;
  - on `stream_interrupted` or a network error, sets `status: "error"` with message "Connection lost. Retry.";
  - aborts on unmount or conversation change;
  - ignores `send` while `status === "streaming"`.
